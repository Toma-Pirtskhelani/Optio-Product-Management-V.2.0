# schemas/g2.md — G2 pass output columns

Populates the spine in `schemas/merged-table.md`. Every field there is mandatory here;
this file adds what G2 specifically exposes and what it specifically hides.

**Source class: `SELF-DECLARED` for everything below, with two partial exceptions noted in
§4.** A product is on G2 because someone put it there. Set `source_class: SELF-DECLARED` by
default and justify any row that claims otherwise.

---

## 1. What G2 is the source of record for

- What G2 puts in a G2 category, and what it calls that category.
- G2's own stated inclusion criteria for that category.
- Review counts, ratings, and badge/report placement **as G2 computes them**.

**What G2 is not the source of record for:** whether a vendor is real, how large it is, who
its customers are, or whether the category corresponds to anything a buyer recognizes.
Anything of that kind sourced from G2 is `SINGLE-SOURCE` at best and needs a
`REVEALED-BEHAVIOR` source to corroborate.

---

## 2. Category-level rows

One row per G2 category encountered. `entity_type: category`.

| Field | Notes |
|---|---|
| `raw_name` | **The category name exactly as G2 prints it.** Never cleaned |
| `normalized_name` / `registry_id` | From `industry-registry.md`. Append if no match — never force |
| `category_url` | Exact URL |
| `category_definition_verbatim` | G2's prose definition of the category, quoted in full |
| `inclusion_criteria_verbatim` | **The full "To qualify for inclusion in the … category, a product must:" block, every bullet, verbatim.** `UNKNOWN` if not shown — and then this category's count is non-comparable to every other |
| `parent_category_raw` | G2's own hierarchy above this category, verbatim |
| `child_categories_raw` | Verbatim list, if shown |
| `related_categories_raw` | Verbatim, if shown — this is where taxonomy boundary disagreement becomes visible |
| `product_count_declared` | The count **G2 states** (e.g. "122 Products") + `_grade` |
| `product_count_visible` | How many were actually captured |
| `pagination` | `none` / `page X of Y` / `unknown` |
| `sort_order` | Whatever sort G2 showed. `UNKNOWN` if not stated |
| `filters_active` | Verbatim, or `none` |
| `scope_verdict` / `ruling_id` | Ruled per `logs/boundary-rulings.md`, not assumed |
| `source_boundary_verbatim` | Where G2's boundary differs from this study's functional definition — quoted, logged as a conflict |
| `capture_date`, `rung`, `source_class`, `source_language`, `paste_id`, `raw_file` | Spine |

**`product_count_declared` vs `product_count_visible` is the whole pagination discipline in
two columns.** If they differ, every absence in this category is `ABSENT-IN-VISIBLE-PAGE`.
Never `ABSENT-ENUMERATED`. No exceptions, no "it was probably all of them."

## 3. Product-level rows

One row per product **per category** — a product in five categories is five rows, because
the category cluster is the unit of analysis and `cluster_size` is a property of G2's rules,
not of the product.

| Field | Notes |
|---|---|
| `entity_name_raw` | Product name **exactly as printed**, including any suffix or parenthetical |
| `entity_name_canonical` | This study's key |
| `vendor_name_raw` | Selling entity as printed, where G2 distinguishes it from the product |
| `product_url` | Exact G2 profile URL |
| `entity_type` | `product` |
| `position_in_list` | Rank as displayed. Meaningless as quality, essential as sampling metadata |
| `promoted` | `yes` / `no` / `UNKNOWN` — sponsored, "Sponsored", or ad-marked placement |
| `star_rating` + `_grade` | As printed |
| `review_count` + `_grade` | As printed |
| `satisfaction_score` / `market_presence_score` + `_grade` | Where shown |
| `grid_placement_raw` | Leader / High Performer / Contender / Niche, **verbatim**, with the report name and period |
| `badges_raw` | Verbatim. Badges are marketing assets — record them, never treat them as evidence of quality |
| `pricing_shown` + `_grade` | Verbatim as displayed, incl. currency and unit. `UNKNOWN` where "Contact us" |
| `entry_level_price_verbatim` | Quoted, not parsed into a number |
| `seller_hq_stated` | Only if G2 states it. **Never inferred from the name** |
| `languages_supported_stated` | Verbatim, where listed |
| `categories_listed_raw` | **Every G2 category this product appears in, verbatim** → feeds `category_cluster` |
| `cluster_size` | Count of the above, within `taxonomy_id: g2` |
| `presence` | Spine value |
| `entity_status` | `active` unless G2 states otherwise or a two-capture comparison shows removal |
| `capture_date`, `rung`, `source_class`, `source_language`, `paste_id`, `raw_file` | Spine |

## 4. Source-class discipline specific to G2

Default `SELF-DECLARED`. Two fields have a **partial** `REVEALED-BEHAVIOR` character and are
still not sufficient for corroboration on their own:

- **`review_count`** — reviews are user actions leaving traces. But review acquisition is
  vendor-driven (campaigns, incentives, gift cards), so the count measures **review-collection
  effort** at least as much as customer volume. Record it as `SELF-DECLARED` with a note; do
  not promote a row to `corroborated: yes` on it.
- **`grid_placement_raw`** — computed by G2 from reviews plus market-presence inputs, several
  of which are vendor-supplied. `SELF-DECLARED`.

**Therefore: a G2 row can never reach `corroborated: yes` against another `SELF-DECLARED`
source** — including Gartner Peer Insights and marketplace listings. Corroboration needs a
`REVEALED-BEHAVIOR` source (`merged-table.md` §5).

**Pay-to-play must be visible.** `promoted` and `badges_raw` exist so a reader can see which
positions were bought. A sponsored top-of-list placement carries no information about the
market and must never be read as one.

## 5. Failure sampling in a G2 pass

G2 does not mark decline the way Gartner does, so a G2 pass **cannot satisfy failure sampling
on its own.** State that in the pass's failure-coverage statement rather than implying the
market has no failures.

What a G2 pass *can* contribute, all requiring two dated captures of the same URL in
`sources/raw/`:
- products present in an earlier capture and absent in a later one — `entity_status:
  UNKNOWN` until distinguished from pagination, then `delisted` if the total count corroborates;
- categories whose `product_count_declared` drops materially between captures;
- profiles marked acquired, discontinued, or merged by G2 itself.

**A single capture can never establish that anything disappeared.** One capture plus a memory
of how it used to be is model memory, which is not a source.

---

## 6. Language obligation

G2 is an English-first, US-headquartered platform. A G2 pass is `source_language: en` on
nearly every row, and that is a **structural undercount of non-Anglophone vendors**, not a
description of the market (`CLAUDE.md` §6).

Where G2 serves localized category pages, capture the localized URL as a **separate row with
its own `source_language`** — and if the localized and English pages list different products
for the same category, that is a `conflict`, logged, both sides carried. It is one of the few
places G2 can expose its own export-marketing bias.

Every G2 pass output ends with: *"N of M rows are `source_language: en`. Vendors without
English-language export-marketing spend are structurally invisible to this pass."*

---

## 7. Reject conditions (in addition to `merged-table.md` §7)

1. `inclusion_criteria_verbatim` paraphrased instead of quoted.
2. `product_count_visible` recorded without `product_count_declared`, or vice versa when both
   were on the page.
3. Any absence written as `ABSENT-ENUMERATED` where the two counts differ.
4. A category row with no `scope_verdict`.
5. `promoted` left blank on a list capture where sponsorship was visible.
6. Any row claiming `corroborated: yes` where the second source is also `SELF-DECLARED`.
